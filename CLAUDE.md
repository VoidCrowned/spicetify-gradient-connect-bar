# CLAUDE.md — Gradient Connect Bar

A Spicetify extension that recolours Spotify's **Connect bar** (the "Playing on …" strip below the player while audio plays on another device) with one solid colour or a multi-stop gradient. It is a port of [Gradient Progress Bar](https://github.com/VoidCrowned/spicetify-gradient-progress-bar) (GPB, `E:\phpstorm_ws\spicetify-gradient-progress-bar`) pointed at a different element. It must coexist cleanly with themes, with GPB and with other extensions, because it's meant for the Spicetify Marketplace, not just the author's setup.

Everything under *Verified facts* was confirmed from the live DOM (Spotify 1.3.4.258; re-verified by the self-test on 1.3.5.3058, 169/170 with the one miss fixed in v0.4.1; Spicetify 2.45.3, Hazy with Custom colour `#8372fd`) or from the patched xpui CSS. Don't re-derive it and don't "improve" on it by guessing. If something depends on the live Spotify DOM and can't be known from this repo, **put a check for it into the self-test** instead of assuming.

**GPB is read-only from this project.** Read it for reference; never modify, commit to or push anything there, and never read or write its storage key.

## Verified facts — Spotify DOM

Markup of the Connect bar (Spotify 1.3.4.258). Hashed classes are unstable; never use them anywhere.

```html
<aside data-testid="now-playing-bar" class="main-nowPlayingBar-container …">
  <div class="main-nowPlayingBar-nowPlayingBar">…</div>
  <div class="alQyi9QVSuY6ma3oYVy6 encore-bright-accent-set rQwECrSefr6Lg_zK9rQh">
    <svg data-encore-id="icon" style="--encore-icon-fill: var(--essential-base); …">…</svg>
    <button data-encore-id="textLink" …><span class="… encore-internal-color-text-base">Playing on überall</span></button>
  </div>
</aside>
```

- **The selector, defined once as `SELECTOR`:**
  `[data-testid="now-playing-bar"] > .encore-bright-accent-set:has(> svg[data-encore-id="icon"] + button[data-encore-id="textLink"])`. Specificity 0,4,2. `UNSCOPED` is the same without the `[data-testid="now-playing-bar"] >` prefix; the self-test counts both to tell "bar absent" from "parent changed".
- The bar is **removed from the page** when playback returns to this computer. It only exists while playing on another device. On 1.3.4.258 it was the only `.encore-bright-accent-set` on the page; on 1.3.5.3058 two play buttons' inner spans carry the class as well (`span.encore-bright-accent-set` with an icon-wrapper child), so never select by the class alone. `SELECTOR` and `UNSCOPED` both still match exactly one element, because of the `:has(> svg[data-encore-id="icon"] + button[data-encore-id="textLink"])` part.
- Background: `background-color: var(--background-base)`; `background-image` is `none`. Height 24 px, `border-radius: 4px`, no held Web Animations.
- Text and icon colours come from `--text-base` (the span's `encore-internal-color-text-base`) and `--essential-base` (the icon's inline `--encore-icon-fill`). Both `#000000` under Hazy. The icon and text sit at the **right-hand end** of the bar. The text span is `span[data-encore-id="text"].encore-text-body-small-bold.encore-internal-color-text-base`: **14 px, weight 700** (1.3.5.3058), icon 16 × 16; the preview strip's label matches (self-test).
- Spicetify's patched `xpui-snapshot.css` defines `.encore-bright-accent-set { --background-base: var(--spice-button-active); --text-base: var(--spice-sidebar); --essential-base: var(--spice-sidebar); … }` (Spotify's own, unpatched: `#1ed760` and `#000`). That's the fallback for the bar's colour before the bar has been seen (`barBase()`), and for its text colour (`spotifyTextColour()`).

## Verified facts — coexistence

### Hazy theme ([Astromations/Hazy](https://github.com/Astromations/Hazy))

- `--spice-button` is set **at runtime** as an inline style on `:root` by `hazy.js` on every `songchange`: with *Custom color* on, the user's fixed colour; otherwise a colour taken from the album art. Never read theme colours from a theme's `color.ini` — only the live computed value, or better, `var(--spice-button)` in CSS.
- `--spice-rgb-button` is stale under Hazy: it keeps the colour scheme's value while `--spice-button` changes. Tint with `color-mix(in srgb, var(--spice-button) 30%, transparent)`, never `rgba(var(--spice-rgb-button), …)`.
- Hazy calls `document.getElementById("color-input")` and styles generic classes and elements globally (`.slider`, `.toggle`, `.toggleWrapper`, `select`). Never use those ids, classes or elements.

### Gradient Progress Bar

Runs side by side: its own `<style id="gpb-style">`, storage key `gpb:settings`, global `__gpb`, and its own capture-phase `contextmenu` listener for the song progress bar (`[data-testid="playback-progressbar"]`). Nothing of ours may match its target, and nothing of its may match ours; the self-test checks both when `window.__gpb` exists.

### Spicetify PopupModal

`Spicetify.PopupModal` is a custom element (`generic-modal`). `display()` rebuilds its innerHTML, appends our content into its `<main>` and appends itself to `<body>`; `hide()` removes it. Its **overlay click handler hides the modal when `.GenericModal` doesn't `contains(event.target)`** — so a click whose target we detach during dispatch closes the modal. **Never remove or replace the clicked element synchronously in a click handler; defer with `setTimeout(…, 0)`.**

Themes may give the dialog `backdrop-filter` or `transform` (Hazy blurs it), which makes the dialog the containing block for `position: fixed` descendants. **No large popovers inside the modal**, only the small dot menu; everything bigger goes inline.

**Bottom spacing (GPB #48):** Hazy's `app.css` gives `.main-trackCreditsModal-container` `padding-bottom: 32px`. `evenPopupBottom()` sets inline `padding-bottom: 0` on that container and the content's `padding-bottom` to its own `padding-left`, on this `display()`'s elements only. **Never a global rule** for Spicetify's popup classes.

### Clipboard

**Spotify's client refuses `navigator.clipboard.writeText`; use `Spicetify.Platform.ClipboardAPI.copy()`.** `writeClipboard(text)` tries `ClipboardAPI.copy` → `navigator.clipboard.writeText` (each raced against 1.5 s) → `document.execCommand("copy")` from a hidden textarea inside the modal root.

### Spicetify entry points — #34, #35

The settings open by **right-click on the bar** (only during remote playback), the **shared top-bar button**, our **profile-menu entry** and `__gcb.openSettings()`. The top bar and the profile menu are registered in parallel (`registerSpicetifyEntries()`), neither is the other's fallback (GPB #45). On Spotify 1.3.4+ with Spicetify ≤ 2.45.3 both need the maintainer's spicetify-fixes extension to show up (GPB #55); without it they stay hidden or off screen, and right-click and `openSettings()` still work. **Never ship a `MenuItem` swap, the top-bar class workaround or any other global Spicetify fix in this extension.**

**Shared top-bar button, protocol 1 (#34)** — one button for GCB and GPB:

- `window.__gradientBars = { protocol: 1, owner, entries, register(entry), refresh(), click(anchor) }`, created by whichever extension starts first (a synchronous check-and-set in `joinGradientBars()`, called before start-up awaits anything). The owner is the only one that creates a `Spicetify.Topbar.Button`. The shape is frozen for protocol 1; later protocols may only add fields.
- Joining: protocol 1 → `register()` our entry, no button (role `member`). Another protocol → leave it alone, own button opening our settings (role `own button (protocol N)`). None → create it (role `owner`), register, create the button (waiting up to 15 s for `Spicetify.Topbar`).
- Entries `{ id, name, open }`, sorted by name. Label: one entry → its name; two → "Gradient bars". `click()`: one entry → `entries[0].open()` directly (decision, Void can flip it); two → toggles the menu.
- Menu: `#gradient-bars-menu` in `<body>`, appended once, hidden, never removed; its own `<style>` inside it; `role="menu"`, items `role="menuitem"` rebuilt on opening only; 8 px below the button, right edges aligned, clamped. Colours: `--spice-card` (fallback `--spice-main`), `--spice-text`, hover/focus `color-mix(in srgb, var(--spice-button) 20%, transparent)`. Opened from the keyboard (the click's `detail` is 0) → focus on the first item; ↑/↓ wrap, Home/End, Enter/Space activate, Escape closes and refocuses the button, Tab closes; outside pointerdown, window blur, resize and scroll close it. Activating hides the menu first, then calls `open()` in the next task. Ids and classes `gradient-bars-`, never `gcb-`/`gpb-`.
- The code is one block between `// ── Shared entry (protocol 1) — keep identical in GCB and GPB ──` and `// ── End shared entry ──`, **identical in both files apart from `SELF`** (`{ id: "gcb", name: "Gradient Connect Bar", open: openSettings }`). It depends only on `SELF`, `ENTRY_ICON` and `window.Spicetify` (plus browser globals). GPB copies it byte for byte (GPB #58): change it in both or neither. `joinGradientBars({ self, key, prefix, createButton })` overrides exist for the self-test's separate test instance only.
- `ENTRY_ICON` is GPB's, byte for byte (a brush over a progress bar), so the button looks the same whoever owns it.
- `status().shared`: `{ protocol, role, owner, entries }`; `status().topbar`: `{ created, connected }`; `status().entryErrors`.

**Profile menu (#35)** — our own entry, not part of the shared button: `new Spicetify.Menu.Item("Gradient Connect Bar", false, openSettings, ENTRY_ICON)`, after waiting for `Spicetify.ReactJSX.jsx` (every 250 ms, max 15 s; `Menu.Item`'s constructor calls it at once, and spicetify-bindings set it only after CLI extensions start, GPB #27). `shouldAdd` is wrapped with `menuItemUsable()` (ported unchanged from GPB): on builds whose `Spicetify.ReactComponent.MenuItem` is Spotify's V2-only item (spicetify/cli#4012) the entry stays hidden instead of breaking the profile menu, and appears by itself once it's fixed. `status().menu`: `{ registered, menuItemUsable }`; `status().apis.ReactJSX`. The self-test environment has `spicetifyFixes` (from `window.__fixes`, `null` when it isn't running, never relied on).

## Hard rules

1. **One injected stylesheet only** (`<style id="gcb-style">`, regenerated). No inline styles on Spotify elements, no stored references to the bar (Spotify removes and re-creates it). Querying the bar on demand to measure it is fine.
2. **Only `SELECTOR`**, defined once. No hashed class names anywhere.
3. Paint with `background-image: linear-gradient(to right, …)`, **opaque colours only** (no `rgba(`, `transparent` or 8-digit hex in the bar's CSS). **Never change `--background-base`** (or `background-color`).
4. `--text-base` / `--essential-base` change **only inside the bar's own rule**, never globally.
5. **No `!important`.** Win by specificity.
6. The entry point is **one capture-phase `contextmenu` listener on `document`** checking `e.target.closest(SELECTOR)`, never a listener on the bar.
7. Never read or write GPB's storage key; both extensions must run at the same time without affecting each other.

`cssProblems(css)` in the self-test enforces 2–5 on every generated stylesheet.

## Rendering — #3, #4, #6

```js
const SELECTOR = '[data-testid="now-playing-bar"] > .encore-bright-accent-set:has(> svg[data-encore-id="icon"] + button[data-encore-id="textLink"])';
```

```css
${SELECTOR} {
  background-image: linear-gradient(to right, <stops>);
  --text-base: <#000000 | #ffffff>;      /* Auto, Black, White; absent for Spotify default */
  --essential-base: <#000000 | #ffffff>;
}
```

- Stops are evenly spaced across the bar's full width. **Static**: nothing follows playback; there are no Spread modes (#6).
- Solid: `linear-gradient(to right, <c>, <c>)`.
- A **theme stop** is emitted as `var(--spice-button, var(--spice-text, #1db954))`, never a resolved hex.
- **No transparency** (Void's decision after testing v0.2.0, matching GPB): stops are theme or custom, always opaque. Transparent stops existed in v0.2.0; the 1 → 2 migration removes them.
- **A solid theme colour is inert**: no background rule, the bar keeps its own colour. With default settings the only declarations are the text colour (Auto, see below), which under Hazy is the same black Spotify uses.
- `barImage()` is the one gradient string for the stylesheet, the preview strip and the self-test.

## Text colour — #11–#17

`settings.textColour`: `"auto"` (default) | `"black"` | `"white"` | `"default"`.

- **Black / White** write `--text-base` and `--essential-base` as `#000000` / `#ffffff` into the bar's rule. **Spotify default** writes nothing. **Auto** writes the last calculated choice.
- **Text region (#12):** `measureTextRegion(bar)`: the icon's left edge to the text button's right edge, as fractions of the bar's padding box. The bar is queried on demand, never stored. `textRegion` keeps the last measurement; before the bar has ever been seen (in this session) the whole width `{0, 1}` counts.
- **Samples (#13):** `gradientSamples()`: both region edges, every stop position inside, `SAMPLES_BETWEEN` = 8 evenly spaced points between. Stops are resolved for the calculation only: theme → `getComputedStyle(document.documentElement)` `--spice-button` (via `themeHex()`), custom → its hex. The samples are the opaque stop colours themselves, interpolated in sRGB between them as the browser draws the gradient; no compositing. An inert background samples as the bar's own colour (`barBase()`).
- **Pick:** `pickTextColour()`: WCAG contrast of black and of white against every sample; the colour whose **worst** contrast is higher wins (ties: black). Never an average: a dark stop under the text must not be outvoted by a light gradient (self-test scenario). If both are low, the better one is still used, silently.
- **Write (#14):** `recalcTextColour()` stores `textResult` and calls `applyCss()`, which regenerates the stylesheet with `buildCss(settings, appliedTextColour())`.
- **Triggers (#15),** all through `scheduleTextColour()` (debounced, `TEXT_DELAY` = 100 ms): settings changes (`update()`); the bar appearing or changing (a MutationObserver on the `[data-testid="now-playing-bar"]` aside, `childList` + `subtree` + `characterData`, filtered to direct-child changes and mutations inside the bar; it also watches the aside's parent and re-attaches if the aside is replaced; before the aside exists, a body observer waits for it once); `resize`; and, while `followsTheme()` (a theme stop is active, or the background is inert), `songchange` and `:root` `style` mutations. Hazy sets its colour after the song change, not with it, hence the `:root` observer.
- While the bar is gone, the last region and result are kept; settings changes recalculate with that region.
- **UI (#11):** a *Text colour* row under the Gradient row: a `radiogroup` of *Auto · Black · White · Spotify default* (ported from GPB's Spread row: roving tabindex, ←/→ wrap, Home/End, the checked button filled with `--spice-button` and its label in whichever of `--spice-text`/`--spice-main` contrasts more). **No hint and no warning** under it, in any mode, and nothing in the console (Void's decision after testing v0.2.0: the user picks the text colour and judges the result; #16 superseded). The row sits the modal's normal gap above the preview. The preview's label and icon use the applied colour, or Spotify's own for *Spotify default*.
- **`status().textColour` (#17),** for debugging, plain values only: `mode`, `colour`, `contrast` (worst case for the chosen colour), `black`, `white`, `region` (`from`, `to`, `measured`), `barPresent`. No warning flag or message.

## Data model — #2

`Spicetify.LocalStorage`, key `gcb:settings`:

```json
{ "version": 2, "gradient": false, "textColour": "auto", "stops": [ { "id": "s1", "kind": "theme" } ] }
```

- `kind` is `"theme"` or `"custom"` (with `"color": "#rrggbb"`, opaque). 1–8 stops, unique ids.
- `textColour` is optional and additive: missing → `"auto"` silently (settings saved before #11); any other value is invalid.
- **Migrations:** `migrate()` runs `MIGRATIONS[n]` (version n → n + 1) until the data reaches `SCHEMA_VERSION` (now 2), then `validateSettings()`. A schema change bumps `SCHEMA_VERSION` and adds its step instead of dropping old settings. The self-test checks the loop with a temporary version-0 step.
- **1 → 2 (no transparency):** stops with `kind: "transparent"` or a `#rrggbbaa` colour with alpha `00` are dropped; other `#rrggbbaa` colours keep their RGB; if no stop is left, the defaults. Silent (no warning); an originally empty `stops` stays invalid.
- Invalid or old data without a migration → defaults (written back) + one `[gcb]` warning. Data from a **newer** version → defaults in memory, one warning, the stored value left alone until the next save.
- Apply CSS on every input event; persist debounced (250 ms), flushed on close and unload.

**Presets (#29)** live in their own key, `gcb:presets`, with their own version: `{ "version": 1, "presets": [ { "id": "p1", "name": "…", "settings": { "gradient", "textColour", "stops" } } ] }`. `gcb:settings` and `SCHEMA_VERSION` are untouched; GPB's `gpb:presets` is never read. Every preset's `settings` goes through `validateSettings()`. Invalid entries, duplicate ids and anything beyond **12** are dropped with one `[gcb]` warning per load; an unreadable key or unknown version gives an empty list and one warning. Names are trimmed, 1–24 characters, unique case-insensitively among own presets and the built-ins (a clash gets " (2)", " (3)"…; stored names that clash with a built-in are renamed on load, silently). Own ids `p1`, `p2`…; built-in ids `b:void`, `b:sunset`, `b:aurora`, `b:neon`, `b:fairy`.

**Share codes (#36):** `gcb1:` + base64url (no padding) of `{ "g": 0|1, "x": "a"|"b"|"w"|"d", "s": ["t" | "rrggbb", …] }` (`x` = Auto, Black, White, Spotify default; `t` = theme stop). `decodeCode(text, current)` returns `{ settings, from: "gcb" | "gpb" }` or `null`; it trims whitespace and requires an exact prefix. **`gpb1:`** codes are decoded exactly as GPB's `decodeCode()` does — `g` 0/1, a valid Spread mode `m` (`c`, `a`, `s`), 1–8 valid stops — then `m` is dropped and `current`'s text colour kept. Anything else (unknown prefix, garbage, 9 stops, bad hex, unknown or missing `x`, a `gpb1:` without a valid `m`) → `null`. The five fixtures in #36 are shared with GPB's self-test; Export of the Void built-in with Auto gives exactly `gcb1:eyJnIjoxLCJ4IjoiYSIsInMiOlsiODM3MmZkIiwiNWE4MmZmIiwiODM3MmZkIl19`.

## UI behaviour — #5, #7

Ported from GPB (see its CLAUDE.md for the history); what differs is noted.

- Entry: **right-click the Connect bar** (capture-phase `contextmenu` on `document`, `closest(SELECTOR)`, default prevented, propagation stopped), the shared top-bar button, the profile menu and `__gcb.openSettings()` (see *Spicetify entry points*).
- Layout, top to bottom: Gradient row → **Text colour row** → **Presets row** → **preview strip** → dots and the −|+ stepper → inline picker → action row (*Reset*, centred) → help text last.
- **Preview strip (#7):** `.gcb-preview`, 24 px high, 4 px radius: `background-color` = the bar's own colour (`barBase()`), `background-image` = `barImage()` (or `none` when inert), and a fake "Playing on Device" label with a speaker icon at the right-hand end. The icon has **no `data-encore-id`** and the strip no Encore class, so it never matches `SELECTOR` or `UNSCOPED` (self-test). Many themes hide or blur the player behind the popup, and the real bar only exists during remote playback, so the strip is where changes are judged.
- Gradient switch, dots (left-click selects, right-click menu Duplicate/Remove, drag reorders, Alt+arrows, Delete/Backspace), −|+ stepper, selection rules, inline colour picker, hex field with copy button, two-step Reset: as in GPB.
- The picker has one kind button, **Use theme colour** (*Following theme colour*, disabled, on a theme stop), as in GPB. Editing the colour turns a theme stop into a custom stop. No transparency or opacity control.
- Theme swatches and the preview are kept live while the modal is open (MutationObserver on `:root` `style` + `songchange`), disconnected on close.
- Modal colours only from Spicetify variables.
- **Presets row (#29)**, ported from GPB 1.6.1 (see GPB's CLAUDE.md for the details) without Spread: label *Presets* with **Export** and **Import** on the right; two chip rows (the five built-ins; own presets and **+ Save**). Always two-step: the first click arms a chip (*Apply?*) and previews it in the strip, **text colour included** (`textColourFor()`: Black/White literally, Spotify's own for *Spotify default*, Auto computed for the previewed colours over the last text region); the second click applies. No timeout; Escape, blur or any other input disarms. Undo for 10 s after applying, importing or deleting. + Save and Rename use one inline name field; own chips have a menu (*Rename*, *Update to current colours*, *Delete*). Re-rendering the chips goes through `renderChipsLater()`; clicked nodes are hidden, never removed.
- **Built-ins** (GPB's five, same ids and colours: Void, Sunset, Aurora, Neon, Fairy) change only the colours (gradient on + stops) and **keep the current text colour**; they match the current settings by colours only. **Own presets** save and restore the text colour too; they match on gradient, stops and text colour.
- **Share codes (#36):** **Export** copies `encodeCode(settings)` through `writeClipboard()` and the button itself reads *Copied* with the check icon for 2 s; only if every tier fails does a selected read-only code field show. **Import** is an inline paste field (never `clipboard.readText()`): while it holds a valid code, the strip previews it (text colour included) and the status line reads *Previewing code — Apply to use it*; *Apply* or Enter applies with Undo (*Imported code*, or *Imported code from Gradient Progress Bar* for a `gpb1:` code); an invalid code gets *Not a valid code* and changes nothing.
- `spotifyTextColour()` reads the live bar's text colour only while our rule doesn't set `--text-base` (otherwise it would read our own colour); else the last one read, else `--spice-sidebar`.

## Lifecycle

- `window.__gcb = { version, status, selfTest, openSettings }` is defined at the top of the IIFE, **before any waiting**, so a stuck or failed start-up is visible via `__gcb.status()`. Once registered, `__gcb.menuItem` and `__gcb.topbarButton` hold the profile-menu item and our top-bar button (if we own one).
- Start-up order: settings and presets, the stylesheet (with the text colour), right-click, `joinGradientBars()` (synchronous), then phase *registering entry point* while the profile menu and the top bar register in parallel, then *ready*. The self-test waits up to 21 s for that phase to end.
- Wait only for `LocalStorage`, `PopupModal`, `Player` (warn after 10 s which ones are missing).
- Apply the stylesheet **before** registering the entry point.
- Wrap start-up in `try/catch`; on failure set `status().phase = "failed"` with the stack and `console.error` it.
- `status()` and the self-test report include a DOM probe (bar and unscoped counts, the aside's children, an outline of every `.encore-bright-accent-set`), so selector breakage after a Spotify update can be fixed from one pasted report.
- No DOM polling for the bar.

## Spotify updates

Spotify auto-updates and wipes Spicetify's patch. After an update: run `spicetify apply`, re-verify the *Verified facts* with the DOM outline from `__gcb.status()` (while playing on another device), update this file's version note, and fix selectors in one commit.

## Development (Windows)

`gradientConnectBar.js` is **symlinked** into Spicetify's `Extensions` folder (`%APPDATA%\spicetify\Extensions`), like GPB's. Developer Mode is on, so `mklink` needs no elevation; PowerShell 5.1's `New-Item -ItemType SymbolicLink` still asks for admin, so use `mklink`:

```powershell
cmd /c mklink "$env:APPDATA\spicetify\Extensions\gradientConnectBar.js" "E:\phpstorm_ws\spicetify-gradient-connect-bar\gradientConnectBar.js"
spicetify config extensions gradientConnectBar.js
spicetify apply
spicetify watch -e                                     # reload on save
```

Devtools must be enabled (`spicetify enable-devtools`). The maintainer's setup: Hazy theme with Custom colour on, GPB enabled.
